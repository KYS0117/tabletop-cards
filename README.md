# 🃏 테이블탑 카드 — 실시간 멀티플레이 카드 샌드박스

친구들과 같은 테이블에 접속해서 카드를 **직접 집고, 옮기고, 뒤집고, 돌리고, 섞으며** 원하는 규칙으로 노는 웹사이트입니다.
정해진 게임 규칙은 없습니다. PC(Windows)와 휴대폰(안드로이드·아이폰) 브라우저가 같은 방에서 함께 플레이할 수 있어요.

- 프론트엔드: React + TypeScript + Vite
- 백엔드: Node.js + TypeScript + Socket.IO
- 저장소: **서버 메모리**만 사용합니다 → ⚠️ **서버를 재시작하거나 다시 배포하면 모든 방과 카드 상태가 사라집니다.**

## 1. 현재 구현 상태

### ✅ 1단계(MVP) — 구현 완료

| 기능 | 내용 |
|---|---|
| 닉네임 / 방 만들기 / 코드 입장 | 6자리 방 코드, 초대 링크 복사(`?room=코드`), 최대 8명 |
| 같은 테이블 실시간 공유 | 입장 즉시 현재 테이블 전체 동기화 |
| 트럼프 54장 덱 | 조커 2장 포함, 서버에서 섞어서 시작 |
| 카드 집기·이동·내려놓기 | 잡은 지점이 커서/손가락 아래 유지, 집으면 떠오르는 효과, 놓으면 그 자리에 고정 |
| 다른 사람의 조작이 실시간으로 보임 | 끄는 도중의 위치를 초당 약 25회 전송 + 받는 쪽에서 부드럽게 보간, 잡은 사람 이름표·커서 표시 |
| 회전·뒤집기 | Q/E 15°, 90°, 더블클릭/더블탭 뒤집기 |
| 카드 겹치기 | 그냥 겹쳐 놓기(시각적 겹침)와 **더미에 합치기**(더미 위에 놓을 때만)를 구분 |
| 덱에서 1장 뽑기 | 더미를 끌면 맨 위 1장이 딸려 나옴 / 메뉴에서 손패로 뽑기 |
| 덱 셔플 | 서버에서 암호학적 난수로 섞음, 순서는 누구에게도 전송하지 않음 |
| 비공개 손패 | 소유자에게만 카드 정보 전송, 다른 사람은 장수만 앎 |
| 실시간 상태 동기화 | 위치·앞뒤·회전·더미·잠금 상태를 서버가 최종 결정 |
| 방장 초기화 | 확인창 후 테이블과 모든 손패 초기화 |

### ✅ 2단계 중 미리 구현한 것
여러 장 선택(Shift+클릭, 영역 선택, 모바일 다중 선택 모드) · 여러 장 동시 이동 · 한 줄 정렬 · 더미 만들기(묶기) · 더미 합치기 · 더미 전체 이동(⠿ 손잡이) · 여러 장 뽑기 · 모두에게 나눠주기 · 펼치기 · 더미 뒤집기 · 맨 위로 올리기 · 복제/삭제(권한 확인) · 겹친 아래 카드 선택 · 우클릭/길게 누르기 메뉴 · 확대/축소/이동 · 손패 순서 변경·부채꼴 · 뒷면으로 내기 · 테이블 배경 4종 · 카드 크기 3단계 · 그림자/애니메이션 끄기 · 방장 이전 · 강퇴 · 접속/퇴장 알림 · 재접속 시 손패 복원

### ⏳ 아직 구현하지 않은 것 (완성됐다고 표시하지 않음)
- 커스텀 카드 이미지 업로드, 카드 뒷면 이미지 변경, 커스텀 덱 저장/불러오기 (3단계)
- 게임 상태 저장/불러오기 (현재 메모리 전용)
- 방 비밀번호, 강퇴한 사람 재입장 차단 (강퇴된 사람도 코드를 알면 새 플레이어로 다시 들어올 수 있음)
- 남의 손패 일부만 보여주기(공개 손패), 몰래 보기(peek) 같은 세부 규칙 도구
- 서버 여러 대로 확장 (지금은 서버 1대 기준)

> 📐 구조 분석·성능 측정 결과와 새 게임을 추가하는 방법은 **[ARCHITECTURE.md](ARCHITECTURE.md)** 에 정리되어 있어요.

> 💡 "단어 카드 덱"은 커스텀 카드 구조 확인용으로 넣은 글자 카드 덱입니다. `shared/cards.ts`에 원하는 단어를 넣어 바꿀 수 있어요.

## 3. 내 PC에서 실행하기 (Windows + VS Code, 처음 하는 분 기준)

### 3-1. 준비물
1. **Node.js 20 이상 (LTS 권장)** — https://nodejs.org 에서 "LTS" 버전을 받아 설치 (설치 중 옵션은 기본값 그대로).
2. **VS Code** — https://code.visualstudio.com

설치 확인: VS Code를 열고 메뉴 **터미널 → 새 터미널**에서 아래를 입력합니다.
```
node -v
npm -v
```
`v20.x.x` 이상이 나오면 준비 완료입니다.

### 3-2. 실행
1. 받은 zip 파일의 압축을 풉니다. (예: `C:\Users\나\Documents\tabletop-cards`)
2. VS Code에서 **파일 → 폴더 열기**로 `tabletop-cards` 폴더를 엽니다.
3. **터미널 → 새 터미널**을 열고 아래 두 줄을 차례대로 입력합니다.
```
npm install
npm run dev
```
4. 터미널에 아래처럼 나오면 성공입니다.
```
[server] 🃏 테이블탑 카드 서버 실행 중: http://localhost:3001
[client]   ➜  Local:   http://localhost:5173/
[client]   ➜  Network: http://192.168.0.12:5173/
```
5. 브라우저에서 **http://localhost:5173** 을 엽니다.
6. 같은 PC에서 친구 역할을 테스트하려면 **다른 브라우저**(예: Chrome과 Edge) 또는 **시크릿 창**을 하나 더 열어 같은 방 코드로 들어가세요. 같은 브라우저의 탭을 여러 개 열어도 탭마다 다른 플레이어로 들어갑니다.

종료는 터미널에서 `Ctrl + C` 입니다.

### 3-3. 자주 나는 오류
| 증상 | 해결 |
|---|---|
| `npm : 이 시스템에서 스크립트를 실행할 수 없으므로…` (PowerShell) | VS Code 터미널 오른쪽 위 `∨` → **Command Prompt**로 바꿔서 다시 실행. 또는 PowerShell에서 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 실행 후 `Y` |
| `'npm'은(는) 내부 또는 외부 명령…이 아닙니다` | Node.js 설치 후 VS Code를 완전히 껐다 다시 켜기 |
| `EADDRINUSE: 3001` 또는 5173 | 이미 실행 중인 서버가 있음. 다른 터미널을 닫거나 PC 재시작 |
| 화면에 "서버에 연결하는 중…"만 계속 | 서버 터미널에 오류가 없는지 확인. `npm run dev`로 서버·화면이 **둘 다** 실행돼야 함 |
| 휴대폰에서 접속이 안 됨 | 아래 3-4 참고 (방화벽 허용) |

### 3-4. 같은 와이파이의 휴대폰으로 테스트
1. PC와 휴대폰을 **같은 와이파이**에 연결합니다.
2. `npm run dev` 터미널에 나온 **Network 주소**(예: `http://192.168.0.12:5173`)를 휴대폰 브라우저에 입력합니다.
3. 처음 실행할 때 Windows 방화벽 창이 뜨면 **"개인 네트워크" 허용**을 눌러 주세요. 이미 거부했다면 *Windows 보안 → 방화벽 → 앱 허용*에서 Node.js를 허용합니다.
4. 휴대폰은 **가로 화면**을 추천합니다. (세로에서도 모든 기능 사용 가능)

> 개발 모드에서는 Vite가 `/socket.io` 요청을 3001번 서버로 넘겨주기 때문에 휴대폰도 같은 서버에 연결됩니다.

## 4. 인터넷에 배포하기 (친구들이 각자 집에서 접속)

### 방법 A (추천): 서비스 하나로 배포 — Render
서버가 빌드된 웹사이트 파일까지 함께 제공하므로 **주소 1개**, **CORS 설정 불필요**, WebSocket 문제도 가장 적습니다.

1. GitHub 계정을 만들고 이 폴더를 새 저장소에 올립니다. (VS Code 왼쪽 "소스 제어" → "GitHub에 게시"를 누르면 쉬워요. `node_modules`는 `.gitignore`로 제외됩니다.)
2. https://render.com 가입 → **New + → Web Service** → 방금 올린 저장소 선택
3. 아래처럼 입력합니다.

| 항목 | 값 |
|---|---|
| Root Directory | (비워 둠) |
| Runtime | Node |
| Build Command | `npm install --include=dev && npm run build` |
| Start Command | `npm start` |
| Instance Type | Free (테스트용) |

4. **Environment** 에 `NODE_VERSION` = `22` 를 추가합니다. (`PORT`는 Render가 자동으로 넣어 줍니다)
5. 배포가 끝나면 나오는 주소(예: `https://my-cards.onrender.com`)를 친구들에게 보내면 됩니다.

⚠️ Render 무료 요금제 주의사항
- 무료 웹 서비스는 15분 동안 HTTP 요청이나 WebSocket 메시지가 하나도 들어오지 않으면 잠자기 상태가 됩니다. 누군가 접속해 있으면 Socket.IO가 주기적으로 신호를 주고받으므로 보통 깨어 있지만, 모두 나가면 잠들고 **그때 방이 전부 사라집니다**. 다시 접속하면 깨어나는 데 수십 초가 걸릴 수 있어요.
- Render는 무료 웹 서비스를 언제든 재시작할 수 있어요. 재시작되면 진행 중인 방도 사라집니다. 오래 안정적으로 쓰려면 유료 요금제를 쓰거나, 나중에 상태 저장 기능(3단계)을 추가하세요.

### 방법 B: 화면과 서버를 따로 배포
예) 화면은 Netlify/Vercel, 서버는 Render.

**서버 (Render Web Service)**
- Build Command: `npm install --include=dev`
- Start Command: `npm start`
- Environment: `CORS_ORIGIN` = 화면 주소 (예: `https://my-cards.netlify.app`, 여러 개면 쉼표로 구분)

**화면 (Netlify 예시)**
- Base directory: (비워 둠), Build command: `npm install --include=dev && npm run build`, Publish directory: `client/dist`
- Environment variable: `VITE_SERVER_URL` = 서버 주소 (예: `https://my-card-server.onrender.com`)
- ⚠️ `VITE_SERVER_URL`은 **빌드할 때** 들어가므로, 값을 바꾸면 화면을 다시 배포해야 합니다.

### 연결 문제 해결 (CORS / WebSocket)
| 증상 | 원인과 해결 |
|---|---|
| 브라우저 콘솔(F12)에 `CORS policy` 오류 | 서버의 `CORS_ORIGIN`에 화면 주소를 **정확히**(https 포함, 끝의 `/` 없이) 넣었는지 확인 |
| `Mixed Content` 오류 | https 화면에서 http 서버로 접속 중. 서버 주소도 `https://` 사용 |
| 계속 "다시 연결하는 중…" | 서버가 잠들었거나 재시작 중일 수 있음. 서버 주소에 `/healthz`를 붙여 열어 보고 `ok`가 나오는지 확인 |
| 회사/학교 와이파이에서만 안 됨 | WebSocket이 막힌 네트워크일 수 있음. Socket.IO가 자동으로 다른 방식(HTTP 폴링)으로 다시 시도하지만, 그래도 안 되면 모바일 데이터로 테스트 |
| 방 코드가 갑자기 "찾을 수 없음" | 서버가 재시작되어 메모리의 방이 사라진 것. 새로 방을 만들어야 함 |

## 5. 조작 방법

**PC**
- 왼쪽 드래그: 카드 집어서 옮기기 (잡은 지점이 커서 아래 유지)
- 더미 드래그: 맨 위 1장 뽑기 · 더미 오른쪽 위 **⠿ 손잡이** 드래그: 더미 전체 이동
- 더블클릭 또는 F: 뒤집기 · Q/E: 15° 회전 (들고 있는 중에도 가능)
- Shift+클릭: 여러 장 선택 · Shift+빈 곳 드래그: 영역 선택 · 선택된 카드를 끌면 함께 이동
- 빈 곳 드래그: 화면 이동 · 마우스 휠: 확대/축소 · 우클릭: 메뉴 · Delete: 삭제(권한 필요) · Esc: 선택 해제

**모바일**
- 한 손가락 드래그: 카드 이동 (빈 곳이면 화면 이동)
- 더블탭: 뒤집기 · 길게 누르기: 메뉴 (PC 우클릭과 같은 항목)
- 두 손가락: 확대/축소 + 화면 이동 (브라우저 화면 자체는 확대되지 않음)
- 카드를 탭하면 아래(가로 모드는 오른쪽)에 뒤집기·회전·손패로 버튼이 나옴
- ☑ 다중 선택 모드: 탭으로 여러 장 선택, 빈 곳 드래그로 영역 선택

**손패**
- 테이블 카드를 화면 아래 손패 영역에 놓으면 내 손패가 됩니다 (나만 내용이 보임)
- 손패 카드를 위로 끌어 올리면 테이블에 내려놓아집니다. "뒷면으로 내기"를 켜면 뒷면으로 놓여요
- 손패 안에서 좌우로 끌면 순서 변경 · 손패 영역 접기 가능

## 6. 직접 확인하는 테스트 방법

PC 1대에서는 Chrome과 Edge(또는 시크릿 창)를 나란히 띄워 A, B로 사용하세요. 휴대폰은 3-4 방법으로 접속합니다.

| # | 테스트 | 확인 방법 |
|---|---|---|
| 1 | 서로 다른 브라우저에서 같은 방 접속 | A가 방 만들기 → B가 코드 입력 → 양쪽 상단 👥 인원이 2 |
| 2 | A가 움직이면 B에 바로 반영 | A가 카드를 천천히 끄는 동안 B 화면에서도 카드가 따라 움직이고 "A" 이름표가 보임 |
| 3 | B가 뒤집으면 A에도 반영 | B가 카드 더블클릭 → A 화면에서도 뒤집힘 |
| 4 | A의 손패를 B가 볼 수 없음 | A가 카드를 손패로 가져감 → B 화면엔 A의 손패 **장수**만 보임. B에서 **F12 → Network → WS(또는 socket.io) → Messages**를 열어 받은 데이터에 A 손패 카드 이름(예: `"H-7"`)이 없는지 확인 |
| 5 | 같은 카드를 동시에 잡기 | A가 카드를 잡고 있는 동안 B가 같은 카드를 끌면 "A님이 잡고 있어요" 알림, 카드는 A만 움직임 |
| 6 | 나갔다 다시 들어오기 | A가 새로고침(F5) → 같은 자리, 같은 손패로 복귀. 휴대폰은 비행기 모드를 잠깐 켰다 끄기 → 자동 재연결 |
| 7 | 두 방이 독립적인지 | 시크릿 창에서 새 방을 만들어 카드 이동 → 다른 방에는 아무 변화 없음 |
| 8 | 확대 상태에서 위치 정확도 | 휠로 확대한 상태에서 카드를 옮김 → 잡은 지점이 커서 아래 유지되고, 확대하지 않은 B 화면에서도 같은 자리에 놓임 |
| M1 | PC 1대 + 휴대폰 1대 | 휴대폰으로 덱을 끌어 1장 뽑기 → PC에 반영 |
| M2 | 안드로이드 + 아이폰 + PC 동시 | 세 기기가 같은 방에서 번갈아 카드 이동 |
| M3 | 서로 다른 네트워크 | 배포 후, 한 사람은 집 와이파이, 한 사람은 모바일 데이터로 접속 |
| M4 | 모바일에서 옮긴 카드 → PC | 휴대폰 한 손가락 드래그 → PC 화면에 같은 위치 |
| M5 | PC에서 뒤집은 카드 → 모바일 | PC 더블클릭 → 휴대폰에 앞면 표시 |
| M6 | 휴대폰 화면 회전 | 가로↔세로 회전 후에도 카드 배치가 그대로, 다른 사람과 위치 일치 |

## 7. 개발 중 테스트 결과 (정직한 기록)

이 프로젝트를 만든 작업 환경은 인터넷 패키지 설치가 막혀 있어서 **실제 `socket.io` / `vite` 패키지를 설치해 실행해 보지는 못했습니다.** 대신 아래 방법으로 검증했습니다.

- **타입 검사**: 서버·클라이언트 TypeScript 전체를 `tsc --noEmit`로 검사 (React/Socket.IO 타입은 테스트용 간이 타입 사용)
- **실제 브라우저 자동 테스트**: Socket.IO와 같은 사용법의 **테스트용 대체 연결 모듈**(진짜 WebSocket 사용)로 서버 코드를 그대로 실행하고, Chrome으로 PC 2대 + 휴대폰(터치 에뮬레이션, 가로 844×390) 1대를 동시에 접속시켜 **34개 항목 통과** (구조 정리 후에도 다시 실행해 모두 통과)
  - 위 표의 1~8번, M1·M4·M5·M6에 해당하는 시나리오
  - 터치 드래그, 더블탭, 길게 누르기 메뉴, 두 손가락 핀치(브라우저 화면 확대 없음 확인), 세로 회전
  - 손패 ↔ 테이블, 뒷면으로 내기 시 정체 미전송, 더미 합치기, 다중 선택 이동, 더미 전체 이동, 섞기 후 순서 미전송
  - 방장 초기화(확인창), 방장 퇴장 시 방장 이전, 일반 플레이어에게 방장 도구 미표시
- **보안 테스트 11개 통과**: 남의 손패 카드 id로 내기, 일반 플레이어의 초기화/강퇴/삭제, 잘못된 회전값, 과도한 id 개수, 남이 잡은 카드 강제 이동·섞기, 비정상 좌표(NaN, 10억), 틀린 토큰으로 입장 → 모두 서버에서 거부 또는 범위 제한

**아직 확인하지 못한 것 (직접 확인 필요)**
- 진짜 `socket.io` 4.8 / `vite` 6 패키지로 설치·실행 (`npm install` 후 `npm run dev`, `npm run build`) — 사용한 API는 Socket.IO 4의 기본 기능(`to`, `volatile`, ack 콜백, `sockets.sockets`)만입니다.
- 실제 아이폰 Safari / 안드로이드 Chrome 기기 (자동 테스트는 Chrome의 모바일 에뮬레이션)
- 서로 다른 네트워크(와이파이 ↔ 모바일 데이터)에서 배포 버전 접속
- 실제 휴대폰에서의 체감 성능 (8명 + 카드 216장 조건은 에뮬레이션으로 측정 — ARCHITECTURE.md 3장)

문제가 생기면 브라우저 F12 콘솔 오류와 서버 터미널 출력을 함께 알려 주세요.

## 9. 알려진 한계

- **메모리 저장**: 서버 재시작·재배포·무료 호스팅 잠자기 시 모든 방이 사라집니다.
- **서버 1대 전제**: 서버를 여러 대로 늘리면 방 상태가 나뉘므로 Redis 어댑터 + 공유 저장소가 필요합니다.
- 카드 충돌(겹침) 판정은 카드 중심점 기준이라, 아주 비스듬히 돌린 카드를 더미에 합칠 때 판정이 살짝 너그럽습니다.
- 손패 카드가 많으면 겹쳐서 표시됩니다 (가로 스크롤 대신 실제 손패처럼 겹침).
- 잡고 있는 카드는 15초 동안 아무 움직임이 없으면 자동으로 잠금이 풀립니다. 연결이 끊긴 사람의 잠금은 즉시 풀립니다.
- 방장이 20초 이상 연결이 끊기면 다음 사람에게 방장이 넘어갑니다. 30분 넘게 돌아오지 않은 사람은 자리가 정리되고 손패는 테이블에 뒷면 더미로 내려놓아집니다.
